L1 回答一次外部交互如何完成：模型侧由 Model 把 wire 与 transport 配成一对，经 call 或 stream 打开回复；工具侧以 EffectKind 为统一的交互内容，经 ToolServer 注册与执行；MCP 与人工介入是两条入适配。两张图 9 个类，另有两个跨页引用（Wire、Tool，虚线框，详见 L0）。

本系列：L0 契约 · L1 调用 · L2 执行 · L3 编排 · L4 应用 · L5 宿主 · 横切面

L1-1 · 模型调用：配对、搬运、擦除

Model 的两个公有字段就是一次配对：wire 管发什么，transport 管怎么走。DynModel 把两者擦除到只剩操作；Streamed 是一次已打开的回复，finish 把它折成 Response。

读法：一次模型调用等于 Model 配对 wire 与 transport，call 或 stream 打开 Streamed，finish 折叠为 Response；DynModel 是擦除到只剩操作、可克隆共享的形态。收拢未画：Transport 的 blanket 实现（一份实现覆盖一切 HttpClientExt，rig-reqwest 等只提供 client）；Local transport 的 Step 与 Steps；tungstenite 的流式角色。Wire 详见 L0-1。

L1-2 · 工具交互：注册、适配、升级给人

交互内容统一为 EffectKind；ToolServer 是注册表，DynamicTool 是运行时分发边界；McpTool 经 TryFrom 转成 DynamicTool；Ask 是人工介入的提问形态。

读法：手写 Tool（L0-2）经 new_with_context 的回调装进 DynamicTool，MCP 工具经 McpTool 转制，统一在 ToolServer 注册；EffectKind 的 ToolCall 变体是被服务的那一份。未连线：Ask 在工作树里没有找到唯一触发点（疑似 run/policy 的审批），故不画调用边。收拢未画：EffectFamily、Answered 与 EffectRecord；MCP 连接 plumbing；按 HandlerKey 索引的分发表与 serve::Serving 见 L4-2。
