D0a · 平台分层：四层各管什么

设计要点：rig-core 是唯一的无 IO 契约与驱动核心，焦点所在；rig-agent 是单体异步运行时（Builder 即 API）；rig-ecs 是 Bevy 内核（Agent / Turn / Call 皆实体）；rig-harness 是 coding-agent 应用壳，只做运行、插件装配与人机交互；门面 rig 与 rig-cli 都是薄皮。依赖永远向下，harness 绝不直连 provider。

READING: rig re-exports rig-core and opens companions behind features · rig-cli launches rig-harness · harness and agent both use core, harness runs on ecs · 6 packages, 6 dependencies.

D0b · 生态：长在核心上的东西

设计要点：方言 wire、向量库后端都只实现核心定义的 trait（Wire / VectorStoreIndex），绝不自立门户；rig-memory 的 Store 被 ECS 的 SessionStore 拿去做会话持久化；rig-tools 是文件与进程工具箱，供插件拼装；rig-cassette 只观测 providers 的流量做录制回放，不进运行时路径。

READING: providers realize Wire, vector stores realize VectorStoreIndex · cassette observes provider traffic · memory and tools use core types · plugins assemble tools · 7 packages, 2 realizations + 5 dependencies.
