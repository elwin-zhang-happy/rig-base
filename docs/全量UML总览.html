Rig 全量 UML · 分层穿线总览

L0–L5 与横切面的穿线总览。S0 一张图把六层穿成两条线（库主线与 ECS 支线）加一个横切面；S1–S7 每层一张摘要，每图至多 8 个锚点类，完整成员、签名与关系见各分册。类名、签名与数字取自当前工作树，重复实现收拢为省略号。

本系列：L0 契约 · L1 调用 · L2 执行 · L3 编排 · L4 应用 · L5 宿主 · 横切面 · 总览

图例 · 六种关系

全文共用这一套线型词汇。空心三角是继承与实现，菱形在属主端，普通箭头是关联与依赖。

S0 · 穿线：一句 prompt 穿过六层

两条线一个面。上排是库主线：launcher 的 run 把 Invocation 交给 Agent，prompt/resume 产出 AgentRunner，Runner 沿 drive_agent 循环驾驶无 IO 的 AgentRun，AgentRunStep 落到 Model/ToolServer 的 call/stream/dispatch，最终打到 Wire::encode 与 Tool::call。中排是 ECS 支线：Spawner 造 agent，Deliver 投递，7 阶段 Stage 泵 Effect，经 Handlers 表分发，与主线在 Serve 处汇合。下排是横切面：Session/Store 记会话，EffectLog 记 effect，Usage/Span/Witness 做观测，只依赖 L0。

READING: 上排是库路径，中排是 ECS 路径（ALT PATH：同一 launcher 启动；ADAPTS：同一 Serve 汇合），下排是横切面。每个站点注明归属 crate 与分册出处；⇢ 链到本页摘要与各分册详图。

S1 · L0 契约摘要：调用经过谁、状态和能力在哪

Wire 绑定一种 Operation（encode 是纯函数，不碰传输）；CompletionRequest 带走 chat_history/tools/documents，CompletionResponse 带回内容块与用量；Tool 是唯一的行为契约；VectorStoreIndex 被 blanket 实现为名 search_vector_store 的 Tool。详情见《L0 契约层类图》。

读法：Wire—BINDS→Operation（一对多）；Operation 经 REQUEST/RESPONSE 关联请求与回复类型；请求以字段持有消息；向量库以 Tool 形态被调用。收拢未画：Decoder（classify/decode）与 Fold（absorb/finish）；Mode；ToolDefinition/ToolContext；Session/Conversation 的落盘形态见 S7。全部住在 rig-core。

S2 · L1 调用摘要：配对、搬运、擦除与统一交互

Model 是 wire+transport 配对（两半皆为公有字段）；DynModel 把配对擦除到只剩操作；Streamed 是已打开的回复，finish 把它折成 Response；ToolServer 是注册表，DynamicTool 是运行时分发边界；EffectKind 六变体统一交互内容。详情见《L1 调用层类图》。

读法：配对（Model 持 wire、经 transport 发送）、擦除（erase 到 DynModel）、打开（call/stream 得 Streamed，finish 折叠）；工具侧 ToolServer 注册 DynamicTool，服务 EffectKind。收拢未画：Transport 的 blanket 实现与 Local transport；McpTool 经 TryFrom 转 DynamicTool；Ask（ECS 提问组件）。模型侧住 rig-core，ToolServer 住 rig-agent。

S3 · L2 执行摘要：推进链与无 IO 状态机

AgentBuilder 装配→Agent 启动→AgentRunner 驾驶→AgentHook 转向；Runner 驱动无 IO 的 AgentRun，next_step 说要什么，driver 做完经 model_response/answer 反馈回来；TurnPolicy 按轮落门。详情见《L2 执行层类图》。

读法：prompt/resume 产 Runner，Runner 经 drive_agent 循环推进；Run 是 sans-IO 状态机（RUN_FORMAT=5），门分两级：本轮 TurnPolicy，跨轮 Hook。收拢未画：RunSpec（预算与输出）与 per-run 覆盖；PreparedRequest::apply；PendingToolCall 的 Execute/Malformed；HookStack。全部住在 rig-agent。

S4 · L3 编排摘要：生与走、调度泵

多 agent 即多 entity：Spawner 造（Root/ChildOf/Like 三 origin），ForkAgent 复制，Deliver 投递；Stage 七阶段泵 Effect，Turn 把一次请求收成一集，Running 把工作扇到线程池。详情见《L3 编排层类图》。

读法：生（spawn/fork）与走（deliver）是上排，调度泵是下排；Turn 的 reply 指回 Effect，Running 在线程池里完成它们。收拢未画：CurrentAgent（当前 agent）与 SavedAgent（落盘）；TurnCall 之外的调用家族（SideCall 等）；Prepare/Review/Gate 各插件相位；RunPlugin 的 run 契约。全部住在 rig-ecs（CurrentAgent 住 rig-harness）。

S5 · L4 应用摘要：观察与服务边界

用例三件事：观察靠 MultiTurnStreamItem 事件加 RunEvents 定界 feed；分发靠 Serve 边界经 ErasedHandler 注册进 Handlers 表，ModelAdapter 与 ToolAdapter 是两边的入适配。AgentRunner 本体见 S3。详情见《L4 应用层类图》。

读法：Runner 发事件、开 feed；run 服务 effect 不直调模型或工具，只查 Handlers 表。收拢未画：TypedRun/Extractor；ToolAdapter/RetrieveAdapter；Intercept/Recorder/Layer 中间件；ToolServerHandle::attach。Serve 与适配器住 rig-core，Handlers 与观察项住 rig-agent。

S6 · L5 宿主摘要：启动与消费

发起是 rig 二进制的 run（读 Home 布局、认领 session、传 Invocation），命令形状由插件上报的 AgentDescription 决定；消费是三面前端加一种库嵌入（ChatBotBuilder 吃 Agent 吐聊天循环）。详情见《L5 宿主层类图》。

读法：启动三步读布局、认会话、传参数；Invocation 由 description 认出，由 run 传下；库嵌入是 ChatBotBuilder 吃 Agent 吐聊天循环。收拢未画：PrintPlugin（headless stdio）与 AcpPlugin（编辑器桥）；HelpersPlugin；Home 下的 settings/plugins 布局；rig plugin/project/build 等管理命令。run 住 rig-cli，Home/Invocation/Description 住 rig-harness-protocol。

S7 · 横切面摘要：记住什么、观测什么

持久化记住发生过什么（会话日志与 effect 日志两套），观测回答正在发生什么（用量进 span，轨迹走 Witness）。两面只依赖 L0。详情见《L6 横切面类图》。

读法：Session 经 Store 读写，SessionLog 先攒后追；录制与回放是同一卷日志的两端；观测不经过 handler 表。收拢未画：DirStore/MemoryStore；Checkpoint；SpanBuilder/SpanCombinator；SessionStore（ECS 资源包装）。Store/Session 住 rig-memory，EffectLog 住 rig-cassette，Usage/Witness 住 rig-core。

S8-1 · 方言群：两棵树与扩展点

方言即数据：OpenAI-shape 25 方言与 Anthropic-shape 8 方言都是 Dialect 常量，分别挂在共享泛型线 Chat 与 Messages 上；openai_vendor!/anthropic_vendor! 宏按方言生成各 vendor 的 from_env/new；各 vendor 的差异收进自家的 ProviderExtension（类型化 Options/Extras，21 处）。线种与操作全表见 S8-2。

读法：Chat/Messages 是唯二的手写 completion 泛型线，其余 vendor 只出 Dialect 常量 + ProviderExtension + 模型名常量。收拢未画：各 vendor 的模型名常量；OpenAI 的 Responses 与 Chat 双路由；按名连接 Catalog::connect("vendor/model") 经 registry 查方言。数字：Dialect 常量 25+8，extension 21 处，wire 结构体 19 个（见 S8-2）。

S8-2 · 操作、线种、后端与传输：三张全表

操作 11 种（9 种住 rig-core 的 operation，2 种由 provider 自定）；线种 19 个；向量后端 13 个（core 内 InMemory 加 12 个 companion）；传输 6 路（blanket HTTP 加 reqwest/tungstenite/http、Local 与 gRPC）。右下是本总览明确不覆盖的三块。

读法：线种名即操作名（Chat/Messages/Responses→Completion，Embeddings→Embedding，余类推，type Op 以源码为准）；13 后端各以自有 Filter 实现 VectorStoreIndex（top_n/top_n_ids）；传输与线种在 Model 配对（见 S2）。收拢未画：测试替身（MockToolIndex、Scripted 等）；rig-http 的 framer/SSE 件；Audio/Image 的 modality 细节。
