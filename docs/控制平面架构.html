改造设计 · §3–§10

控制平面架构

rig 留作数据平面（L0 / L1：消息、wire / driver、工具契约、effect 记录），你补控制平面（执行、编排、用例、持久化、观测）。 四张图各回答一个问题：主栈怎么分层、三场景怎么走同一条栈、effect 七阶段怎么转、journal 怎么记和恢复。 依赖只向下，横切面只依赖 L0。

图 1 · layer stack

主栈六层，两面横切

层的判据是组合关系：上层把下层组合成更大的行为单元。L4 是唯一组合根，有图走 L3，无图直达 L2。 持久化与观测是被各层调用的面，不是层：它们接收事件，但只依赖 L0 的可序列化类型，所以可替换、可测试。

依赖规则 R1 紧邻依赖（L4 例外，可选 L3 或 L2）· R3 横切面被各层写入但只依赖 L0 · R5 跨层只传 L0 可序列化类型 · R4 适配器向内依赖端口 · R6 L0 不碰 runtime 与 IO。检验句：每一层只能用紧邻下层的公开契约，上层回调下层即画错。

图 2 · process

三场景是同一条栈的三种走法

单次调用不另开通道：它要么是 L2 的一步执行，要么是单节点工作流。自主性不是新引擎，是 L2 的策略装配。 三条路径起点都是 L5 宿主，差别只在是否经过图解释器，以及 L2 装了多少策略。

路径：S1 L5 → L4 → L2 → L1 → L0；S2 L5 → L4 → L3 → L2 → L1 → L0；S3 与 S1 同路，L2 多装四组策略。 场景二的模型节点、工具节点在 L2 里都是单次执行单元，Agent 节点是多步执行单元，L3 不为不同节点写不同调度。 工具与 skill 快照随 run 持久化，MCP 离线仍可回放。

§3.7 · one call

一次调用穿过各层

  • L4 创建 run：run_id 加工具 / skill 快照，写 run_started
  • L3（有图）选下一节点，写 node_started
  • L2 取下一步：单步执行或 AgentRun 状态机推进
  • L1 调度 effect：effect_begin → settled，模型、工具、MCP、skill、人工走同一个入口
  • L0 表达请求与响应，适配器执行真实交互
  • 返回时逐层归一化，写节点事件与检查点，投影到 trace 与指标，事件流交回宿主

§5.2 · primitive

Effect 是唯一的执行原语

  • 一套调度意味着录制、回放、重试、预算、审批、观测只实现一次
  • 门是策略（L2 工具门 / 模型门、L3 节点门），begin = human_requested，settled = human_answered
  • 长连接订阅是新 effect 类型，不是新通道

mini-rig · today

mini-rig 对照

  • wire.rs / driver.rs 已是 L1 形状：encode 纯函数，Transport 是唯一 IO
  • effect.rs 七阶段是 L1 加 L2 简化版；缺 journal、检查点、人工 effect
  • agent.rs::run 是 L2 单循环；缺停止、预算、压缩、转向

图 3 · state machine · lifecycle

Effect 七阶段，一帧跑到不动点

一个 effect 沿主轨推进，执行后回到 Review，Commit 派生新 effect（工具调用或下一轮模型调用）或落 settled。 拒绝不是丢弃：被拒的工具调用仍产生一条 tool result（refused: …）回填给模型，会话顺序按调用声明顺序，不按完成顺序。

门是策略，人工交互仍是一条 effect：begin 写 human_requested，settled 写 human_answered，中间有检查点。 现状插件三方法：prepare 改请求，gate 拒绝，review 改结果。目标补齐：Commit 先写 journal 再产生可见效果； Gate 可挂起为人工 effect（human_requested 到检查点到 human_answered）；settle_tool 按 call_id 槽位回填； 确定性 effect id 加去重。拒绝回 Review 后，工具走回填路径，模型走结束路径。

图 4 · timeline

持久化：事件溯源加检查点

追加日志记录事实，检查点保存快照加游标，恢复时加载快照再重放游标之后的事件。 人工中断挂在第二条时间线上：只有 human_requested 时保持挂起，有 human_answered 即应用决策继续。

恢复语义是至少一次加幂等：跨进程做不到恰好一次，所以复杂度放在工具边界（幂等键、副作用等级、人工兜底），而不是全局事务。 settled 之后崩溃则重放直接用结果，不重调。在途 effect 三分：重试、失败、转人工。

表 1 · 恢复流程：崩溃后任意 worker 接管，单写者租约（§7.2）

§8 · observe

可观测：三个平面，一条关联链

指标不是独立采集的，而是从 effect 事件和 journal 事件投影出来。独立采集会产生第二套事实，和 journal 对不上。 默认只记元数据，正文显式开启加脱敏。打点位置：L4（run 状态）、L3（节点）、L1（模型前后与工具前后）、重试、人工门、检查点。

表 3 · 三个平面的分工
平面内容保留回答
Tracespan 树、耗时、接口状态、错误短到中，头部采样，错误全留这次调用慢在哪、错在哪
Metrics五组：用量、调用次数、接口状态、工具执行、持久化健康长，聚合花了多少、调了多少次、外部服务是否健康
Journal业务事实，可回放按合规，不采样到底发生了什么、能否重建
workflow_run_id → node_id → agent_run_id → turn → effect_id → provider_request_id

工具状态十种：invoked、succeeded、failed、refused、denied、skipped、invalid_args、timeout、cancelled、 uncertain（恢复时无法判断是否已执行）。refused 与 denied 是策略行为，不是错误，不混进失败率。

§14 · i1

所有外部交互都是 effect

都可序列化，否则无法录制、回放、恢复。

§14 · i2

所有执行事实先写 journal

否则崩溃后无法知道发生了什么。

§14 · i3

图是数据，执行器是解释器

否则流程不可存、不可校验、不可迁移。

§14 · i4

上层只组合下层

不反向依赖，否则分层退化成互相调用。

§14 · i5

观测是 journal 的投影

否则出现两套互相矛盾的事实。

§14 · i6

人工介入是持久化中断

不是内存回调，否则审批不能跨进程、不能恢复。
